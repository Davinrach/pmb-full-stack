## Objektivitas
| Objektivitas | Target (Disesuaikan dengan Kondisi Kelompok) |
| --- | --- |
| Pengumpulan Kebutuhan (Requirements) | Dokumen kebutuhan perangkat lunak tersusun dan disepakati, mencakup portal informasi, pendaftaran calon mahasiswa, pengunggahan berkas, pembayaran dan verifikasi, proses seleksi, pengumuman hasil, serta panel Admin/Super Admin. |
| — | Kebutuhan fungsional dan nonfungsional terdokumentasi, termasuk pengelolaan tiga program studi, gelombang pendaftaran, akun dan hak akses pengguna, pengumuman melalui web/email, ekspor data pendaftar ke Excel, serta kebutuhan responsivitas dan keamanan. |
| — | Aturan bisnis dan validasi disepakati serta terdokumentasi, meliputi NIK 16 digit, kelengkapan isian formulir empat tahap, persyaratan berkas, batas ukuran dan format unggahan, alur pembayaran transfer bank dengan verifikasi manual, serta alur seleksi tes/wawancara sesuai ketentuan PMB. |
| — | Batas ruang lingkup dan riwayat revisi kebutuhan tercatat, termasuk fitur yang masuk ruang lingkup dan fitur yang tidak dikembangkan pada versi ini, seperti payment gateway otomatis atau SMS OTP apabila belum disepakati. |
| Desain Sistem (Design) | Dokumen desain arsitektur sistem diselesaikan dan ditinjau, mencakup pemisahan frontend Next.js, backend REST API berbasis Go/Gin, dan database MySQL sesuai rancangan teknologi final. |
| — | Desain basis data relasional/ERD dan kamus data tersedia serta konsisten dengan kebutuhan, termasuk entitas pengguna, calon mahasiswa, asal sekolah, orang tua, berkas, pembayaran, program studi, gelombang, dan data seleksi. |
| — | Kontrak endpoint REST API dan desain keamanan terdokumentasi, termasuk autentikasi, otorisasi berbasis peran (RBAC), validasi permintaan, serta pembatasan akses ke berkas pendaftar sesuai rancangan final. |
| — | Rancangan UI/UX responsif tersedia untuk landing page, formulir pendaftaran bertahap, dashboard calon mahasiswa, halaman pengumuman, dan dashboard admin/CMS termasuk pengelolaan konten yang memang masuk ruang lingkup. |
| Implementasi (Implementation) | Frontend diimplementasikan menggunakan Next.js (App Router), TypeScript, dan Tailwind CSS sesuai rancangan, mencakup halaman publik, autentikasi, formulir pendaftaran, dashboard calon mahasiswa, serta panel admin. |
| — | Backend diimplementasikan menggunakan Go/Gin, ORM, dan MySQL sesuai keputusan teknologi final, dengan pemisahan modul yang mendukung pengelolaan handler, model, middleware, akses basis data, dan utilitas. |
| — | Alur utama terintegrasi antara frontend, backend, dan basis data, mulai dari pendaftaran/login, pengisian formulir, unggah berkas, pengiriman bukti pembayaran, verifikasi admin, pembaruan status seleksi, hingga penyampaian pengumuman dan pembuatan dokumen PDF yang disepakati. |
| — | Validasi sisi klien dan server diterapkan secara konsisten untuk field wajib, format NIK, ukuran dan tipe berkas yang diizinkan, serta pembatasan tindakan berdasarkan hak akses pengguna. |
| Pengujian Sistem (Testing) | Skenario Black-Box untuk alur calon mahasiswa dan admin disusun serta dijalankan; hasil aktual dibandingkan dengan hasil yang diharapkan dan dicatat pada lembar pengujian. |
| — | Pengujian kasus negatif dan edge cases mencakup isian wajib kosong, format NIK tidak valid, pengiriman formulir berulang, unggahan berkas dengan tipe/ukuran yang tidak diizinkan, serta akses ke fitur atau data tanpa hak yang sesuai. |
| — | Pengujian White-Box/unit pada fungsi backend kritis dilakukan sesuai ketersediaan kode dan cakupan pengujian, seperti validasi input, proses hash/verifikasi kata sandi, middleware autentikasi dan RBAC, aturan perubahan status pendaftaran, serta validasi berkas. |
| — | Pengujian integrasi memverifikasi pertukaran data frontend–API–MySQL dan keluaran yang disepakati, termasuk notifikasi/pengumuman, ekspor Excel, dan dokumen PDF jika fitur tersebut telah diimplementasikan. |
| — | Hasil pengujian, bukti pengujian, status lulus/tidak lulus, dan catatan defect terdokumentasi; temuan kritis ditangani atau dicatat secara eksplisit sebelum sistem dinyatakan siap digunakan. |
| Penerapan (Deployment) | Lingkungan aplikasi dikonfigurasi sesuai lingkungan target, termasuk pengelolaan variabel lingkungan dan secret, konfigurasi CORS, koneksi basis data, serta kredensial autentikasi tanpa menanamkan secret secara langsung pada kode. |
| — | Frontend dan backend berhasil di-build serta dijalankan pada lingkungan target, dan aplikasi dapat diakses melalui alamat yang ditetapkan dengan fitur utama yang terhubung ke basis data. |
| — | Migrasi/skema basis data dan data master awal berhasil disiapkan, termasuk data tiga program studi dan konfigurasi gelombang pendaftaran sesuai ketentuan PMB STAICI. |
| — | Pemeriksaan awal setelah penerapan (smoke test) memastikan halaman utama, autentikasi, alur pendaftaran, akses admin, dan koneksi basis data berfungsi pada lingkungan target. |
| Pemeliharaan (Maintenance) | Dokumentasi operasional tersedia untuk pengelola, mencakup pengelolaan program studi dan gelombang, pemeriksaan berkas/pembayaran, pembaruan status seleksi, pengumuman, serta ekspor data sesuai hak akses. |
| — | Prosedur penanganan bug dan pencatatan error tersedia agar gangguan dapat ditelusuri dan diperbaiki; audit log perubahan data admin diterapkan apabila telah ditetapkan sebagai kebutuhan pada SRS final. |
| — | Prosedur backup dan pemulihan basis data serta dokumentasi teknis pemeliharaan tersedia untuk mendukung keberlanjutan operasional sistem. |
